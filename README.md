# 리듬 탄막 멀티플레이 게임 (MVP)

친구들과 소규모로 플레이하기 위한 실행 가능한 최소 구현체입니다.
서버 1대만 띄우면 브라우저로 접속해서 바로 플레이할 수 있습니다.

## 프로젝트 구조

```text
rhythm-game/
├─ README.md                    # 프로젝트 설명, 실행 방법, 게임 규칙, 파일 구조
├─ client/                     # 브라우저에서 실행되는 프론트엔드
│  ├─ index.html               # 게임의 화면 및 UI 요소 구성
│  ├─ style.css                # 랜딩, 로비, 게임 HUD와 네온 테마 스타일
│  └─ src/
│     ├─ main.js               # 화면 전환, 로비 UI, 서버 이벤트 연결
│     ├─ game.js               # 게임 루프, 플레이어 이동, 대시, 충돌, 렌더링
│     ├─ network.js            # WebSocket 연결 및 메시지 송수신 추상화
│     ├─ obstacles.js          # 장애물 표시 및 장애물-플레이어 충돌 판정
│     └─ themes/
│        ├─ BaseTheme.js       # 테마가 구현해야 할 기본 배경/효과/장애물 스타일
│        ├─ NeonPulseTheme.js  # 현재 사용되는 네온 펄스 시각 테마
│        └─ ThemeRegistry.js   # 테마 등록 및 ID 기반 조회
├─ server/                     # Node.js + TypeScript 백엔드
│  ├─ package.json             # 서버 의존성 및 build/start/dev 명령
│  ├─ tsconfig.json            # TypeScript 컴파일 설정
│  ├─ src/
│  │  ├─ index.ts             # HTTP/WebSocket 서버와 API 진입점
│  │  ├─ roomManager.ts       # 방, 플레이어, 진행 단계와 생명/부활 상태 관리
│  │  ├─ audioAnalysis.ts     # 오디오 디코딩, FFT 분석, 비트/장애물 타임라인 생성
│  │  ├─ youtube.ts            # 유튜브 메타데이터 조회와 오디오 추출
│  │  └─ types.ts              # 방, 플레이어, 곡, 타임라인의 공용 TypeScript 타입
│  └─ uploads/                 # 업로드 및 유튜브 추출 오디오 저장 위치
```

### 디렉터리와 파일별 역할

#### 루트

- `README.md`: 설치·실행 방법, 게임 규칙, 설계 의도와 전체 파일 구조를 설명합니다.

#### `client/`

- `index.html`: 랜딩 화면, 로비, 게임 화면, 결과 화면을 정의하고 `main.js`를 불러옵니다. 닉네임·방 코드 입력, 곡 설정, 캔버스, 오디오 요소, 게임 결과 버튼도 이 파일에 선언되어 있습니다.
- `style.css`: 화면 레이아웃과 네온 색상, 패널·버튼·입력창·플레이어 목록·곡 슬롯·HUD·게임 캔버스의 시각 스타일을 담당합니다.
- `src/main.js`: 클라이언트 진입점입니다. 방 생성/참가, 로비 플레이어와 곡 슬롯 렌더링, MP3 업로드, 유튜브 곡 확인 및 사용 요청, 게임 시작/스테이지 전환/결과 화면을 처리합니다.
- `src/network.js`: WebSocket을 생성하고 서버 메시지를 타입별 핸들러에 전달합니다. 방 ID와 플레이어 ID를 보관하며 JSON 명령을 서버로 전송합니다.
- `src/game.js`: `requestAnimationFrame` 기반 게임 루프를 실행합니다. 키보드 이동, 대시와 무적 시간, 플레이어 위치 동기화, 부활 요청, 장애물 충돌, 비트 펄스, 플레이어 애니메이션과 Canvas 렌더링을 담당합니다.
- `src/obstacles.js`: 장애물 이벤트의 경고/활성 표시 시간을 계산하고, 레이저·충격파·벽·웨이브·탄환 등 각 유형의 충돌 수학과 Canvas 렌더링을 구현합니다.
- `src/themes/BaseTheme.js`: 테마의 기본 인터페이스와 기본 배경, 블룸 효과, 주파수 대역별 장애물 색상 스타일을 제공합니다.
- `src/themes/NeonPulseTheme.js`: 그라디언트 배경, 움직이는 그리드와 파티클, 비트 반응형 블룸, 장애물별 네온 팔레트를 구현합니다.
- `src/themes/ThemeRegistry.js`: 테마를 등록하고 ID로 조회합니다. 현재 `neon_pulse` 테마를 기본 등록하며, 새 테마를 추가할 때 확장 지점으로 사용합니다.

#### `server/`

- `package.json`: Express, WebSocket, Multer, FFmpeg, 유튜브 오디오 추출 라이브러리와 TypeScript 실행 명령을 정의합니다.
- `tsconfig.json`: `src/**/*.ts`를 엄격한 TypeScript 설정으로 검사하고 `dist/`에 CommonJS JavaScript로 빌드하도록 지정합니다.
- `src/index.ts`: Express 정적 파일 서버와 업로드/유튜브 API를 만들고 WebSocket 연결을 처리합니다. 게임 시작 시 오디오 분석을 호출해 타임라인을 생성하고 모든 클라이언트에 스테이지 시작 시각과 함께 배포합니다.
- `src/roomManager.ts`: 방 생성·참가·퇴장, 방장 권한, 곡 슬롯, 플레이어 위치, 피격·생명·부활, 스테이지 성공/실패/재시작 상태를 관리합니다.
- `src/audioAnalysis.ts`: FFmpeg로 오디오를 PCM으로 변환한 뒤 FFT와 주파수 대역별 에너지 변화를 분석합니다. 킥·스네어·멜로디·하이햇·드롭 온셋을 장애물 이벤트와 비트 펄스가 포함된 결정적 타임라인으로 변환합니다.
- `src/youtube.ts`: `youtube-dl-exec`를 통해 유튜브 제목·썸네일·재생 시간을 조회하고, 확인된 링크의 오디오를 MP3로 추출합니다.
- `src/types.ts`: 곡 슬롯, 장애물 유형, 비트 펄스, 타임라인, 플레이어, 방 상태 등 클라이언트와 서버가 공유하는 도메인 타입을 선언합니다.
- `uploads/`: 업로드된 MP3와 유튜브에서 추출한 오디오를 저장합니다. 런타임에 생성되는 파일이므로 저장소에 포함할 필요가 없는 개인 데이터 디렉터리입니다.

### 데이터 흐름 요약

1. 방장이 MP3를 업로드하거나 유튜브 링크를 확인하고, 서버가 오디오 파일과 곡 정보를 저장합니다.
2. 방장이 게임을 시작하면 `audioAnalysis.ts`가 곡을 분석해 스테이지 타임라인을 생성합니다.
3. `roomManager.ts`가 모든 클라이언트에 같은 타임라인과 `serverStartTime`을 전달합니다.
4. 각 클라이언트의 `game.js`가 같은 기준 시각에 음악과 장애물을 재생하고, 위치·피격·부활 상태는 WebSocket으로 동기화합니다.

이 구조 덕분에 장애물을 각 클라이언트가 독립적으로 생성하지 않고, 서버가 만든 동일한 타임라인을 모두가 재생할 수 있습니다.

## 실행 방법

### 사전 준비
- Node.js 18 이상
- (권장) 시스템에 ffmpeg가 설치되어 있으면 유튜브 오디오 추출이 더 안정적입니다.
  - macOS: `brew install ffmpeg`
  - Ubuntu: `sudo apt install ffmpeg`

### 서버 설치 및 실행
```bash
cd server
npm install
npm run build
npm start
```
기본적으로 `http://localhost:8080` 에서 서버가 실행되며, 같은 서버가 `client/` 폴더의
정적 파일도 함께 서빙합니다. 즉 서버만 켜면 브라우저에서 바로 접속 가능합니다.

포트를 바꾸려면: `PORT=3000 npm start`

### 개발 중 바로 실행
```bash
cd server
npm install
npm run dev
```

### 친구들과 함께 접속하기 (외부 배포)
- 같은 와이파이: 서버 PC의 사설 IP로 접속 (`http://192.168.x.x:8080`), 방화벽에서 포트 허용 필요.
- 외부 인터넷: 클라우드 VM(예: 오라클 클라우드 프리티어, 라이트세일 등)에 위 설치 과정을 그대로 수행하고
  포트 80/443 또는 원하는 포트를 열어주면 됩니다. HTTPS가 필요하면 nginx + certbot으로 리버스 프록시하세요.

## 게임 규칙 요약
- 1~4인, 8방향 이동, 스페이스 대쉬(대쉬 중 무적, 재사용 대기 0.7초), 쉬프트로 즉시 가속
- 목숨 3개, 피격 시 1개 차감 + 0.8초 무적
- 2인 이상: 사망 후 3초 이내 팀원이 근접하면 목숨 1개로 부활 (횟수 제한 없음)
- 총 3스테이지, 스테이지가 오를수록 같은 곡이라도 장애물 밀도 증가
- 방장이 3개 스테이지의 곡(mp3 업로드 또는 유튜브 링크)을 모두 확인해야 시작 버튼 활성화
- 방장 권한: 다른 사람에게 위임, 추방, 게임 시작, 실패 시 재시작

## 설계 핵심: 왜 모든 플레이어에게 같은 장애물이 나오는가
서버가 곡을 한 번 분석해서 "몇 초에 어떤 장애물이 어떤 파라미터로 나오는지"를 담은
타임라인(JSON)을 만들고, 이걸 모든 클라이언트에 그대로 배포합니다. 클라이언트는
서버가 보내준 스테이지 시작 시각(serverStartTime)을 기준으로 이 타임라인을 재생만
하기 때문에, 클라이언트마다 독립적으로 판단하지 않아도 동일한 패턴이 보장됩니다.

## 알려진 한계 (개인 프로젝트 MVP 기준의 의도적 단순화)
이 소스는 "돌아가는 실물"을 목표로 한 실용적 구현이며, 프로덕션 수준으로 다듬으려면
아래 부분을 개선하는 걸 추천드려요.

- **비트 검출**: 정교한 ML 기반이 아니라 프레임 에너지(RMS) 기반의 온셋 검출입니다.
  비트가 뚜렷한 EDM/댄스 음악에는 잘 맞지만, 잔잔한 곡에는 장애물이 뜸하게 나올 수 있습니다.
- **재생 동기화**: 서버-클라이언트 시간차를 `Date.now()` 차이로만 보정합니다(간이 NTP).
  네트워크 지연이 크면(200ms+) 플레이어 간 화면에 미세한 오차가 생길 수 있습니다.
  더 정교하게 하려면 ping-pong 왕복시간 측정 후 offset을 계산하는 로직을 추가하세요.
- **부활 판정**: 근접 판정이 클라이언트가 보고한 좌표 기반이라 약간의 신뢰가 필요합니다
  (협동 게임이라 치팅 리스크는 낮다고 보고 단순화했습니다).
- **유튜브 오디오 추출**: `youtube-dl-exec`(yt-dlp)를 사용합니다. 유튜브 이용약관을
  직접 확인하시고, 개인 소규모 용도로만 사용하시는 걸 권장드립니다.
- **재접속**: 연결이 끊긴 플레이어는 캐릭터가 즉시 제거되며, 같은 세션으로 재접속해
  이어하는 기능은 없습니다(새 플레이어로 재입장).
- **장애물 종류**: straight/radial/spread/wall/homing 5종 기본 구현입니다. 종류를
  늘리고 싶다시면 `server/src/audioAnalysis.ts`의 `OBSTACLE_TYPES`와
  `client/src/obstacles.js`의 `getBulletsForEvent`에 패턴을 추가하면 됩니다.
